# Анимация Stand для scourgefemale_hd (не завершено)

## Где остановились
- Исходный файл: `scourgefemale_hd.glb` из wow.export v0.2.19 с Export animations (70 МБ, 352 анимации). В репозиторий не добавлен: игровые файлы сюда не кладём.
- В Windows 3D Viewer и в three.js анимация `Stand (ID 0 variation 0)` сломана: голова уходит в грудь, из головы торчит «палка», ноги скрещены.

## Что найдено
- wow.export пишет в канал `translation` не положение кости, а только M2-смещение относительно опорной точки (почти 0). Правильно: `положение покоя узла + смещение из анимации`.
- У пяти костей (`bone_Jaw`, `bone_95`, `bone_WeaponL`, `bone_SpellHandR`, `bone_IndexFingerTipL`) значения смещения около (0, 1.1, ±0.67) и масштаб 0.65/0.8 — это не данные кости. Их каналы отброшены (кость остаётся в позе покоя).
- После исправления голова на месте, «палки» нет (`pose-compare.png`: покой / Stand как есть / Stand исправленный). Файл с одной анимацией — 13 МБ.

## Не подтверждено
- Совпадает ли исправленная поза с игровой (руки почти как в покое, ноги скрещены, голова наклонена). Возможно, неверны и повороты.
- Почему глаза выглядят прикрытыми.

## Следующий шаг
Нужна эталонная выгрузка из wow.export: та же модель, в предпросмотре включена Stand, экспорт в OBJ (OBJ хранит текущую позу) + скриншот предпросмотра спереди. Сравнить вершины OBJ с исправленным GLB на том же кадре. Если совпадёт — добавить GLB (только Stand) в `data/armory_models/` и автозапуск анимации в просмотрщике Оружейной; если нет — по разнице найти, что ещё wow.export пишет неверно.

## Инструменты
- `tools/fix_wowexport_stand.py IN.glb OUT.glb "Stand (ID 0 variation 0)"` — оставляет одну анимацию, исправляет смещения, отбрасывает испорченные кости. Запуск: `python3 -I`.
- `tools/diag_stand_channels.py IN.glb` — список каналов Stand, сильно отличающихся от позы покоя.
